# 验证只能交给时间

判断在事前靠推导保证，在事后靠时间验证。两者之间没有即时的评测。

## 四种手段

| 手段 | 何时给出结果 | 能确认的 |
|---|---|---|
| 推导 | 事前 | 前提成立时，结论成立 |
| 结构 | 当场 | 耦合放错了地方 |
| 测试 | 当场 | 行为符合预期 |
| 时间 | 周期走完之后 | 方向对不对，值不值得 |

前三种确认的都是"做对了没有"。"值不值得"只有第四种能确认。

## 单次结果不算验证

| | 结果好 | 结果坏 |
|---|---|---|
| 判断对 | 应得 | 运气差 |
| 判断错 | 运气好 | 应得 |

只看一次结果，分不清同一列里的两格。

右上和左下都是运气。左下更危险：错的判断得到了奖励。

## 时间提供的两样东西

- 次数。同一个判断重复足够多次，运气相互抵消。
- 周期。一个完整的周期走完，短期对、长期错的东西现出原形。

## 等待期间

写下当时的推导：前提、选项、后果。到期对照。

| 到期时 | 结论 |
|---|---|
| 结果好，前提成立 | 判断对 |
| 结果好，前提不成立 | 运气 |
| 结果坏，前提成立 | 回去查推演，漏了哪个后果 |
| 结果坏，前提不成立 | 判断错 |

没有记录，到期只剩结果，退回上一节那张表。

## 人和 agent 的判断力

一个人或一个 agent 的判断力有没有变好，同样交给时间。

短期内看得见的信号只有一个：开始指出设计里缺的东西。
