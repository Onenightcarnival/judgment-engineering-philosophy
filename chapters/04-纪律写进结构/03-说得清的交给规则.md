# 说得清的，交给规则

一条判断只要说得清，就不靠人记住。

说得清，指写得成一个可检验的终态。

## 分拣

| 判断 | 说得清吗 | 去处 |
|---|---|---|
| `__init__.py` 里只有 import | 说得清 | 规则 |
| 宽泛的 `except` 要显式标明 | 说得清 | 规则 |
| datetime 带时区 | 说得清 | 规则 |
| async 函数里没有阻塞调用 | 说得清 | 规则 |
| 嵌套不超过五层 | 说得清 | 规则 |
| 这里不该用类 | 说不清 | 眼光 |
| 这段逻辑该放在哪一层 | 说不清 | 眼光 |

## 先问有没有现成的规则

```text
__init__.py 中应该只有 import，不应该有实现代码。
看一下 ruff 是否有规则可以配置。
```

- 第一句是终态。
- 第二句把手段交出去。

判断留在自己手里。查找规则、修改配置，交给 agent。

## 规则是凝固的眼光

规则集里的每一条开启、每一条忽略，都是一次判断的存档。

判断做一次。规则执行无数次。

## 提示词里的叮嘱不算规则

| | 提示词里的叮嘱 | 检查里的规则 |
|---|---|---|
| 不照做时 | 没有后果 | 不通过 |
| 上下文变长之后 | 被冲淡 | 不变 |
| 对人 | 无效 | 同样生效 |

## 交出去之后

格式、行宽、导入顺序、嵌套深度，不再需要任何人开口。

评审的注意力留给规则够不着的地方。
