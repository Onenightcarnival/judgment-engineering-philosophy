# 三句话就够了

接收方足够近时，原则只要几句。

```text
代码、文档、注释统一风格要求

1. 声明式。
2. 不自我解释，仅呈现设计结果。
3. 通过结构让读者一眼看明白逻辑。
```

## 效果

| | 不写这三句 | 写了这三句 |
|---|---|---|
| 交付物 | 啰嗦，自我解释 | 清爽 |

## 长度的变化

| 模型能力 | 需要的指令 |
|---|---|
| 弱 | 很长的规则清单，专门去除套话的流程 |
| 强 | 几句原则，其余小修小补 |

指令的长度与接收方的能力成反比。

## 短的三个前提

- 写的人看清了。压缩是眼光的产物。
- 接收方够近。
- 其余的已经交给别的载体。

| 载体 | 管的范围 |
|---|---|
| 规则 | 说得清的 |
| 样板 | 说不清、做得出来的 |
| 原则 | 方向 |

## 第二句

交付物里不出现推理过程，不出现自我评价，不出现"为什么这样写"。

解释由结构承担。

## 同一份文档

设计和架构原则写在一处，给人看，也给 agent 看。

对两者都清晰的文档，只有一种写法。
