# 先定周期，再谈对错

一个观点对不对，看它放在哪个周期里。

## 同一个决定

| 决定 | 短周期里 | 长周期里 |
|---|---|---|
| 复制粘贴一段代码 | 对，最快 | 错，改一处漏三处 |
| 先写测试 | 错，慢 | 对，快 |
| 市场大跌时买入 | 错，继续亏 | 对 |
| 跳过设计直接写 | 对，今天就有东西 | 错，推倒重来 |

没有周期，这四行都没有答案。

## 周期由对象的寿命决定

| 对象 | 周期 |
|---|---|
| 一次性的脚本 | 今天 |
| 一个要上线的功能 | 几个月 |
| 一个核心库 | 几年 |
| 做判断的方式 | 一辈子 |

一次性的脚本按短周期判断，是对的。

## 两个周期冲突时

长的优先。

长周期里的错，短周期里的对补不回来。

## 先对齐周期

讨论之前，先各自说出周期。

| 周期 | 做法 |
|---|---|
| 对得齐 | 讨论 |
| 对不齐 | 不讨论。分歧在周期上 |

## 对 agent

把周期写进指令。

| 指令 | agent 交出的 |
|---|---|
| "写一个脚本统计日志" | 默认按长期维护来写，或按一次性来写，看运气 |
| "一次性脚本，用完即弃" | 短，直接 |
| "这段代码要维护三年" | 带类型、测试、清晰的边界 |
