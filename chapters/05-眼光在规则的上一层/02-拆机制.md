# 拆机制

眼光从拆机制开始。

机制是一个系统的规则、数值和相互作用。懂机制的人预测得出系统的行为，不用等它发生。

## 拆三样

| 拆什么 | 要回答的问题 | 工程里的样子 |
|---|---|---|
| 规则 | 它允许什么，禁止什么 | 生命周期、调用顺序、状态由谁持有 |
| 数值 | 代价多大，收益多大 | 一次调用多少毫秒、多少 token、多少钱 |
| 相互作用 | 它和什么相克 | 和什么组合会出问题，什么场景下它是错的选择 |

数值要算出来。"大概很快"不算数值。

## 拆过之后

占优的做法自己浮出来，不需要讨论。

对机制的理解补得上执行的不足。反过来补不上。

## 不拆的样子

| | 拆过机制 | 没拆过 |
|---|---|---|
| 系统在眼里是 | 一组可推演的规则 | 一个黑盒 |
| 做选择靠 | 推演 | 试 |
| 说得出的理由 | "这样必然会怎样" | "上次这样能行" |
| 环境变了之后 | 重新推演 | 重新试 |

## 对 agent

- 让 agent 先读源码再动手，它的产出基于机制。直接动手，它的产出基于印象。
- 使用 agent 的人，要拆的机制多一样：模型本身。它怎么训练出来的，决定了它默认交出什么。
