# 工具、范式、层级、松紧

眼光判断四件事。逐行的写法不在其中。

## 四件事

| | 问的问题 | 看到的 | 判词 |
|---|---|---|---|
| 工具 | 该用什么来做 | 手写循环做分组、求和、排序 | 这是数据处理，用数据处理的工具 |
| 范式 | 该用什么形态来组织 | 抽象基类、两个子类、一个工厂，只为按格式导出 | 一个函数加一次分支 |
| 层级 | 该在哪一层处理 | 每个函数里都有 try、日志、返回 None | 出错就抛，交给统一的异常处理 |
| 松紧 | 约束该多紧 | 签名要求 `list[int]`，函数体只用到迭代 | 只约束用到的行为 |

## 工具

```python
# 看到的
totals: dict[str, float] = {}
for order in orders:
    totals[order.customer] = totals.get(order.customer, 0.0) + order.amount
ranked = sorted(totals.items(), key=lambda kv: kv[1], reverse=True)
top = [name for name, _ in ranked[:3]]

# 判词之后
top = orders.groupby("customer")["amount"].sum().nlargest(3).index.tolist()
```

## 范式

```python
# 看到的
class Exporter(ABC):
    @abstractmethod
    def export(self, rows: list[dict]) -> str: ...


class JsonExporter(Exporter): ...


class CsvExporter(Exporter): ...


class ExporterFactory:
    _registry: dict[str, type[Exporter]] = {"json": JsonExporter, "csv": CsvExporter}

    @classmethod
    def create(cls, fmt: str) -> Exporter:
        return cls._registry[fmt]()


# 判词之后
def export(rows: list[dict], fmt: str) -> str:
    match fmt:
        case "json":
            return to_json(rows)
        case "csv":
            return to_csv(rows)
        case _:
            raise ValueError(fmt)
```

## 共同点

- 四个问题都在问：这件事该不该在这里、用这种方式做。
- 四个判断都发生在读第一行实现之前。
- 四个判断都只要几秒。
- 四个判断大多写不成 lint 规则。

规则管得到的是写法。写法的上一层归眼光。
