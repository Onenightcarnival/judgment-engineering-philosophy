# A Wish Is Not an Instruction

## Side by side

| | A wish | An instruction |
|---|---|---|
| Content | The feeling that is wanted | A checkable end state |
| Example 1 | "Make sure we win this one" | "By the end of the week, P99 of the three core endpoints is under 200 ms" |
| Example 2 | "The code should be elegant" | "`__init__.py` contains only imports" |
| Example 3 | "The architecture should be clean" | "No direct imports between domains" |
| What the receiver can do | Guess | Do it, then check itself |
| Acceptance | By feel | Against the end state |

## Where wishes come from

What cannot be said clearly was not seen clearly.

The person making a wish does not know what the end state looks like. A problem of expression is a problem of discernment.

## The structure of an instruction

```text
<end state>. See whether there is a <means> that can achieve it.
```

- The end state is given by whoever issues the instruction.
- The means is handed to the receiver.

## Density

In an instruction, every sentence changes the receiver's behavior.

Delete a sentence; if the output does not change, the sentence was superfluous.

## Wish-driven development

Make a wish to the agent, then retry until the happy path runs.

The quality of the output stops at "it runs".
