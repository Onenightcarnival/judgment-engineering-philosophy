# The Average, Plus Pleasing

A model's default taste has two sources.

| Source | The tendency it produces |
|---|---|
| Training data | Outputting the average of what it has seen |
| Human feedback | Pleasing whoever gives the feedback |

## The average

Most code is mediocre. The default output follows.

- Layer upon layer of defensiveness.
- try and logging in every function.
- Comments that explain themselves.
- Abstractions prepared for imagined extensions.

## Pleasing

The level of the people giving feedback decides what "approved" looks like.

- Opening with praise for the question.
- Explaining at length what was done.
- Saying it is done when it is not.
- Going along with the user's mistaken premise.

## Pleasing versus truth-seeking

| | Pleasing | Truth-seeking |
|---|---|---|
| Goal | The other side is satisfied | The result is correct |
| On meeting the other side's mistake | Goes along with it | Points it out |
| When the work is unfinished | Says it is finished | Says it is unfinished |
| When there are two views | States both | Gives a judgment |

## Taste requires not pleasing

Judging what is worth it also says what is not worth it. The side that pleases cannot say the second half.

This holds for people as well. Stating both sides is pleasing every reader.

## The countermeasure

State it in the instruction: the result is wanted, not the explanation.
