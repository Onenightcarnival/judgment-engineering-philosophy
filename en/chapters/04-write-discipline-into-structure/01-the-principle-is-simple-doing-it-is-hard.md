# The Principle Is Simple; Doing It Is Hard

Knowing and doing are two things.

## The principles are all simple

- Commit in small steps.
- Think it through before starting.
- Do not write code for imagined requirements.
- Turn down the requirement that is not worth building.
- Do not change a chosen direction over one week's swing.

None of them needs explaining.

## Where the gap is

A principle needs to be known once. The cost is paid every time.

| Principle | The cost, every time |
|---|---|
| Commit in small steps | Stopping a few more times |
| Think it through before starting | Holding back the urge to begin |
| No code for imagined requirements | Holding back "might as well add it" |
| Turn down what is not worth building | Displeasing someone on the spot |
| Do not change direction over a swing | Watching another direction do better in the short run, and not moving |

## Saying it again does nothing

Repeating a principle adds to "knowing". "Knowing" was never short.

## For agents

An agent knows every principle.

| Written in the prompt | After the context grows |
|---|---|
| "Keep it concise" | Falls back to verbosity |
| "Do not over-engineer" | Falls back to layers of abstraction |
| "Do not swallow exceptions" | Falls back to try plus logging |

Writing the principle into the prompt once more is the same as telling a person once more.

## The way out

There are two:

- Events.
- Structure.
