# Set the Horizon, Then Talk About Right and Wrong

Whether a view is right depends on the horizon it is placed in.

## The same decision

| Decision | Over a short horizon | Over a long horizon |
|---|---|---|
| Copy and paste a block of code | Right: fastest | Wrong: change one place, miss three |
| Write the tests first | Wrong: slow | Right: fast |
| Buy when the market crashes | Wrong: the losses continue | Right |
| Skip the design and start coding | Right: something exists today | Wrong: torn down and redone |

Without a horizon, none of these four rows has an answer.

## The horizon is set by the lifespan of the thing

| The thing | Horizon |
|---|---|
| A throwaway script | Today |
| A feature about to ship | Months |
| A core library | Years |
| A way of making judgments | A lifetime |

Judging a throwaway script on a short horizon is correct.

## When two horizons conflict

The longer one wins.

Being right over the short horizon does not make up for being wrong over the long one.

## Align horizons first

Before discussing, each side states its horizon.

| The horizons | What to do |
|---|---|
| Align | Discuss |
| Do not align | Do not discuss. The disagreement is about the horizon |

## For agents

Write the horizon into the instruction.

| Instruction | What the agent delivers |
|---|---|
| "Write a script to count log entries" | Written for long-term maintenance, or as a throwaway: a matter of luck |
| "A throwaway script, discarded after use" | Short and direct |
| "This code will be maintained for three years" | Typed, tested, with clear boundaries |
